Goal (user, 2026-10-15): port Initial D Arcade Stage 3 (NAOMI 2, gds-0033.chd) to Wii with a nullDC4Wii-style launcher, keeping a Windows build to compare. Approach A (user's choice, confirmed 2026-10-16 as "emulation-based port"): nullDC4Wii core fork in port/emu + NAOMI 2 layer.

Windows: `build-port/idas3wii_run.exe --chd ... [--bios naomi.zip] --cpi 2 --snap-dir D --snap-every N` boots to the title (~frame 4100) and attract mode (manufacturer screen ~13000). BIOS is read straight from MAME naomi.zip (src/core/bios_image.cpp).

Wii (pre-alpha 0.2, 2026-10-16): port/wii/Makefile builds launcher + whole core (DC_PLATFORM=2, nullDC.cpp/mem.cpp excluded). Launch page = CPU choice + BIOS (naomi.zip next to CHD) + controls; src/game/game_runner.cpp runs naomi_Init/Run, maps pads (platform::readGameControls) to JVS, logs [mem] pool stats; exits to loader after the game. Guest memory is demand paged by the MMU (emu/wii/wii_fastmem.cpp: windows RAM 0x0C, VRAM 0x04/0x06, ELAN 0x0A, ARAM 0x20000000; zero page for reads, pool from MEM1/MEM2 tops, zero-page reclaim when low). Texture cache 8 MB (GX_TEX_CACHE_BYTES). BSS 15.8 MB (SH4 code cache 6 MB, ARM7 tables). Not yet tested on hardware or Dolphin — Dolphin may need its MMU option.

Measured footprint: written 55.6 MB (boot zero-fills ~30 MB), non-zero ~39 MB; pool estimate ~40 MB → tight; in-race not measured.

Wii status 2026-10-16: core starts in Dolphin (first DSI crash fixed), but the game jumps into BIOS ROM (A00004B6 RFCR poll) at ~frame 242, right after the first ELAN command, before any DIMM DMA. Windows interpreter at --cpi 1 does NOT do this (not timing). At that point on Windows the game idles at 0C020170 and takes a level-6 IRQ through the HLE dispatcher (0C000600 -> 0C000800 -> game handler 0C20C36C, which flushes store queues into area 2/ELAN). naomi_ReportBiosEntry() traps the exact jump (interpreter per-instruction, recompiler at block compile). Local Dolphin runs: scratchpad dolphin/ (private -u user dir, sdsync with autolaunch.txt "gds-0033.chd rec|int"), see [[dolphin-setup]].

FIXED 2026-10-16: cause was Dolphin ignoring PPC PP (read-only) bits, so the shared zero page got written (RAM page 0 with the HLE exception stubs ended up in it; a zero-fill wiped them). wii_fastmem.cpp now probes protection at init and, when absent, backs pages on first read. The user then saw SEGA / SEGA Rosso / Initial D logos and the main menu, but slow.
